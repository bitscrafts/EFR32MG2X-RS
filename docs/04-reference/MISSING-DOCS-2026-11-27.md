# `missing_docs`, taken seriously

**Date:** 2026-11-27
**Scope:** every library crate in the workspace (33 of them), the two `-sys` crates included
**Verdict:** the lint is installed in all 33 and fires; 0 undocumented public items measured; the only
`allow(missing_docs)` in the tree sits on the two modules that `include!` bindgen output, and the gate
verifies that placement instead of trusting it.

## What the measurement was

`#![deny(missing_docs)]` had been in the HAL's `lib.rs` for months, and in three of the twenty-one
domain libraries. The other twenty-nine crates were not linted at all, so "the crate has no public item
without a doc comment" was true by accident or not at all, and nothing could tell the difference.

Measured crate by crate with the compiler, not by reading the source —
`cargo rustc -p <pkg> --lib -- -D missing_docs`:

| crate | undocumented items | of what |
|---|---:|---|
| `efr32mg2x-i2c-core` | 11 | fields and methods of the slave model in the HAL's `cores/i2c/sim.rs` |
| `efr32mg2x-motion-detection` | 1 | the `ms` field of `Event::FreeFall` |
| `efr32mg2x-xiao-bsp` | 1 | `Module::take` — and it had *another* method's doc |
| `embassy-efr32` | 1 | `Efr32Driver::new` |
| `efr32mg2x-rail-sys` | 2 | `Packet::payload`, `Packet::status` |
| `efr32mg2x-bluetooth-sys` | 58 | fields of `BleEvent`, `RfConfig`, `Configuration`, six sleeptimer entry points, `pump`, `import_failed`, `PSA_CALL_NAMES`, `enable_pairing_with` |
| **total hand-written** | **74** | |

After the fixes, the same command over all 33 crates returns **0**. The two remaining diagnostics
groups — 254 items in `rail-sys`, 600 in `bluetooth-sys` — are bindgen output, treated below.

## Two of the gaps were not gaps, they were misplaced docs

`missing_docs` found two places where a doc comment had been attached to the wrong item, and both had
been hiding behind a green gate because the item that *should* have been documented was not the one the
compiler was looking at:

- `crates/xiao-mg24-bsp/src/module.rs`: `/// Take the peripherals.` and `#[must_use]` sat above
  `Module::hal`, whose own doc block followed immediately. `hal` ended up with two doc comments and a
  `#[must_use]` that did not belong to it, and `take` — the function the sentence describes, and the one
  whose `None` return the caller must think about — had no doc and no `#[must_use]` at all.
- `crates/efr32mg24-bluetooth-sys/src/blocking/stack.rs` and `.../src/stack_init.rs`: the same shape.
  `enable_pairing_with` lost its paragraph to `bonding_confirm`, and `pump` lost its paragraph to the two
  counters it maintains. A reader of the rendered docs saw a function described by its neighbour's text.

Neither is a typo; both are what a lint that counts items rather than reading them is good at catching,
which is the argument for having it on rather than keeping a list of documented items.

Also stale, found in the same pass: `psa.rs` carried an orphaned `# Safety` block ("`data` must point to
`data_length` readable bytes") whose function no longer existed, glued to the doc of `IMPORT_FAILED`. The
safety sentence that is still true was merged into `psa_import_key`, which is the function it describes.

## The two generated modules

`rail-sys` includes `bindings.rs` at the crate root; `bluetooth-sys` already included it inside
`pub mod ffi`. Both files are regenerated by `build.rs` on every build from `rail.h` and `sl_bt_api.h`,
which carry no doc comments bindgen can reach, so documenting them would be rewriting generated code on
every build.

`rail-sys` was changed to the shape `bluetooth-sys` already had: the include moved into
`pub mod ffi` with `#[allow(missing_docs)]` on it, and `pub use ffi::*` at the root keeps every public
path (`rail::RAIL_Init`, `rail::RAIL_Handle_t`) exactly where it was. The lift was verified by
compiling the crate and the HAL that consumes it.

That leaves one exemption per generated module, and the gate checks the exemption rather than assuming
it: each permitted `#[allow(missing_docs)]` must sit on a `pub mod` whose body contains `include!`, and
the module must still exist. A `#[allow]` anywhere else fails the gate, in either form —
module-level or crate-level.

## What the gate does, and why each part is there

`scripts/check-missing-docs.py`, called from `scripts/gate.sh`:

1. **attribute** — every crate's lib root carries `#![deny(missing_docs)]`, unconditional. A
   `cfg_attr`-guarded deny is rejected: a lint on for one feature is off for the build most people use.
2. **allows** — the only `allow(missing_docs)` in the tree is the two entries in `GENERATED_MODULES`,
   and each is verified to sit on an `include!` module. This is what makes check 1 worth anything: one
   `#[allow]` in one module would silence the lint there while the root still spelled the deny.
3. **control** — a fixture crate with an undocumented public item and the same attribute is compiled
   with plain `rustc` and **must fail**; the same item with a doc must compile. Both directions, every
   run. Without this, the checker would only prove that a rule is written down.
4. **floor** — fewer than 30 crates inspected is a failure. A broken `cargo metadata` returning nothing
   would otherwise read as "0 crates, 0 problems", which is the shape of failure this repository has
   paid for before.
5. **`--measure`** — the number, crate by crate, on demand. Not the default because it recompiles every
   crate with different rustc arguments and throws away the gate's cache for the steps that follow.

## Controls, run and recorded

| control | result |
|---|---|
| fixture: undocumented `pub fn` + `deny` | refused, `error: missing documentation for a function` |
| fixture: the same `pub fn` with a doc | accepted |
| remove the doc from `Event::FreeFall::ms` in the real tree | `error: missing documentation for a struct field`; restored, compiles |
| `#![allow(missing_docs)]` added to `xiao-mg24-bsp/src/lib.rs` | checker FAILs: "is crate-level, not module-level" (it is reported by the allow rule, not swallowed by the deny rule) |
| `#[allow(missing_docs)]` on `pub mod adc;` in the HAL | checker FAILs: "does not sit on an `include!` module" |
| `#![deny(missing_docs)]` removed from `gpcrc-core` | checker FAILs: "1 crate(s) do not deny the lint" |
| `--floor 99` | checker FAILs: "only 33 crates inspected, floor is 99" |
| restored tree | PASS, 33 crates, mechanism installed and firing |

## What this does not prove

- **`bluetooth-sys` is the one crate whose lint the gate cannot enforce.** The gate skips that crate
  because its bindgen output does not build from a clean checkout (the vendor headers are gitignored),
  so on a CI runner neither the deny nor the fixtures run against it. Its 58 hand-written items were
  documented and measured here by hand (`cargo rustc -p efr32mg2x-bluetooth-sys --lib -- -D
  missing_docs` → 0), and the checker's attribute/allow checks still cover it statically. When that
  crate becomes buildable in CI, the lint starts being enforced there with no further work.
- **"Documented" is not "useful".** The lint requires a doc comment, not a good one; a `/// TODO` passes
  it. What stands behind the quality of these sentences is review, not a check.
- **Generated code stays undocumented.** 854 items across the two `-sys` crates (254 + 600) carry no
  doc comment by design. Their documentation is the vendor header, and the module doc says so.
- **Doc tests are not run here.** A documented example that does not compile is a different defect,
  covered by whatever runs `cargo test --doc`.
