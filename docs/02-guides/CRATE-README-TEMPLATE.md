# Template — the README a crate shows on crates.io

Copy this file to `crates/<crate>/README.md` and fill the `<<…>>` slots. Everything marked **AUTO** is generated by
`scripts/new-crate-readme.py` from the tree — do not hand-write it, because a hand-written status is a claim nobody
can check. Everything else is a slot for a human, and the ones that say *required* cannot be left empty.

Rules this template exists to enforce:

- **No phase numbers, no tiers, no ✅ lists.** They cannot be verified, and this project has shipped "Phase 5 Tier 2 -
  USART Complete, I2C/SPI/Timers Next" while all three peripherals were implemented, followed by "Phase 2 Complete"
  180 lines later in the same file.
- **No "planned" for something the tree already has.** `grep` the module before writing the word.
- **Three groups for status, never one:** watched on the board (with the numbers), exercised by an example, implemented
  but unreached. "Compiles" is a fourth thing and it is not a status.
- **Every link must resolve inside the package.** `../LICENSE-MIT` is a dead link on the crate page; use the public
  repository URL.
- **Every build requirement the package alone does not satisfy is a documentation obligation** — an impl feature, a
  linker script, a `memory.x` origin. It is the first thing a new user hits and the last thing the author remembers.

## Before publishing this file

```bash
python3 scripts/check-publishable.py     # links, include_str!, and state phrases that lie
cargo publish -p <<crate>> --dry-run     # compiles the package; reads nothing
```

Then download the artefact and read it — the crate page renders *this* file, from the version that was published:

```bash
curl -sL -o /tmp/c.crate https://static.crates.io/crates/<<name>>/<<name>>-<<version>>.crate
tar -xzf /tmp/c.crate -C /tmp/pub
grep -c "<<a phrase that was wrong before>>" /tmp/pub/<<name>>-<<version>>/README.md    # expect 0
```
