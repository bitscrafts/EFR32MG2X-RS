# Session 2026-11-12 — radio, layer audit, and nine chapters of the book

Everything here was done without the board: the user was away, so the work is the part that does not
need hands on hardware. What follows is what is proven, what is not, and where the evidence is.

## Radio: both vendor stacks compile and link

| Crate | Before | Now |
|---|---|---|
| `efr32mg24-bluetooth-sys` | 18 × E0609, never built | **compiles**, and `bt_version` links against the three MSLA blobs |
| `efr32mg24-rail-sys` | could not generate bindings (no headers, no blob) | **compiles**, and `rail_version` links |
| `cmsis-stubs` | did not exist (a copy lived inside bluetooth-sys) | one crate, compiled once, linked by both |
| `efr32mg24-radio` | did not exist | safe layer: `ble_beacon` links; `ble_gatt` staged behind `--features gatt` |

The five defects behind that, in order of how much time they cost:

1. **bindgen emulates anonymous unions** with `__BindgenUnionField<T>` on any Rust target (measured:
   `.rust_target(Stable_1_71)` left the output byte-identical). Payloads are read through `as_ref()`,
   which is `unsafe` and says so.
2. **A flexible array member is not a slice**: `data.value.data[i]` does not compile; the byte comes
   from `as_ptr().add(i).read()`, with the length the header provides.
3. **One attribute handle, two names**: `attribute` in the write event, `characteristic` in the read
   request. Converted once, at the boundary.
4. **`build.rs` did not watch its own C file**, so edits to the CMSIS stubs were not compiled while the
   build reported success.
5. **The `-sys` crate had four examples that never compiled** — wrong module path and a command this
   SDK configuration does not declare. Retired to `_tmp/efr32mg24-rs/retired-ble-examples/`.

Measured load ranges: `ble_beacon` 5856 B and `rail_version` 1316 B, both starting at `0x08006000`.

### What is honestly still missing

- **PSA crypto** for any connectable stack: 8 `psa_*` symbols, no blobs vendored anywhere in this
  project or its archive. `ble_gatt` is therefore staged, not working.
- **emlib** for `RAIL_Init`: `CMU_ClockEnable`, `EMU_DCDCSetPFMXTimeoutMaxCtrl`,
  `SYSTEM_ChipRevisionGet`, `SystemSYSCLKGet`. The sources are Zlib and public; the real device headers
  must come with them, because our 52-line `em_device.h` shim is nowhere near enough for `em_cmu.c`.
- **A radio configuration** (`rail_config.c`) from the Radio Configurator. Without it RAIL initialises
  and transmits nothing.

Full detail: `docs/04-reference/RADIO-NOTES.md`.

## Layer audit: seven violations, five now checks

`docs/02-architecture/LAYER-AUDIT-2026-11-12.md`. The short version: the HAL handed out register
blocks and peripheral singletons, a BSP re-exported the PAC, two facades existed in one crate, two GPIO
implementations existed in one HAL, three examples stole core peripherals, and the crate docs
described 78 MHz / 256 KB / an API that no longer existed. All fixed; the gate now fails on:

```
PASS  examples outside the PAC crate name no PAC type
PASS  no BSP re-exports the PAC
PASS  the HAL exposes no register block publicly
PASS  no example steals a core peripheral
PASS  <crate>: N examples of its own level
```

Also: the carrier crate now enters through `Module` (`hal()`), so the arrow base → module → hal is code
and not only a manifest.

## MVP: the missing write

`pac_mvp_add` never executed because it gated the bus clock (`CMU_CLKEN1.MVP`) and never set the
block's own `EN` bit at `0x04`. A clock gate is not an enable. The example now enables the block, proves
it keeps a write before blaming the program, issues `CMD = INIT|START` (INIT is a qualifier), and on a
timeout reports the status bits and the surviving instruction word. **Still unproven**: whether the
program runs. One flash settles it.

## Book: nine chapters, 164 pages

Written from measurements, not from manuals: 1 (with 1.8 layer boundaries and 1.9 the Silicon Labs
toolchain), 2 (SVD and PAC generation), 3 (build systems), 4 (GPIO), 5 (clocks), 12 (Bluetooth), 14
(testing, from the previous session), 15 (BSP). Numbering renumbered in physical order — the book had
two chapters claiming `ch:chapter-14`.

Two build defects fixed on the way:

- The book was **compiling yesterday's sources**: the tar step preserved `book/latex` while the
  container compiled `latex/`. `BUILD.md` now proves the copy landed (md5) before compiling.
- `\codeinline` inside an argument fails with a message about an unrelated macro. `book/check-tex.py`
  now catches that class, plus minted blocks closed with a markdown fence; it found eleven defects of
  mine before the compiler did.

The host name left the repository: `flash.sh` takes `FLASH_HOST`/`FLASH_USER`, and the book describes
the transport instead of the machine.
