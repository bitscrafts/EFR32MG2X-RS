## 2. Flashing is now guarded, and the guards were exercised

`scripts/flash-lnx.sh <elf> [--confirm] [--run]`:

- dry run by default;
- refuses `load_min < 0x08006000` (Gecko bootloader at 0x08000000-0x08005FFF);
- refuses `load_max >= 0x08180000`;
- requires exactly one CMSIS-DAP probe on lnx;
- writes with `probe-rs download`, then reports success only after
  `probe-rs verify` reads the flash back.

Proof it protects the bootloader, read from the chip before and after a write:

```
before  0x08000000: 20001008 08000171 0800265d 08002201
after   0x08000000: 20001008 08000171 0800265d 08002201
```

A control image with `p_paddr` patched to 0x08000000 is refused (exit 3).

### Defect found: every image carried a PT_LOAD inside the bootloader

Before `--nmagic` was added to `.cargo/config.toml`, each ELF had a 372-byte
`PT_LOAD` at `0x08000000` (the ELF header, page-aligned down to the 64 KiB
boundary). No section lived there. `probe-rs` skips that segment — verified by
reading the bootloader's own vector table back from flash — but openocd and
Simplicity Commander are not known to. After the fix: `load_min=0x08006000`,
three segments.

## 3. Verification without eyes

Two independent read paths, both read-only:

| script | what it reads | what it proves |
|---|---|---|
| `read-led-lnx.sh` | `PORTA_MODEL` mode7, `PORTA_DOUT` bit7, `PORTA_DIN` bit7 | the pad is configured as output and electrically follows the latch |
| `read-mailbox.sh` | 0x2003_F000 (magic/seq/status/len/message) | the firmware reported its own result as text |
| `measure-blink-rate.sh` | mailbox `seq` twice + wall clock | the toggle rate, hence the blink period |
| `read-pin-lnx.sh` | any GPIO DOUT bit, N samples | a pin toggles (generic) |

`read-led-lnx.sh` also states what it does **not** prove: that the LED sits on
PA7 and that the LED itself works. Only light proves light — the operator
confirmed the double-blink pattern visually, which is the one piece of evidence
SWD cannot produce.

### probe-rs can wedge its own CMSIS-DAP session

Reading the whole 1.5 MiB flash in one `probe-rs read` wedged the session
(`Command ID in response (0x14) does not match sent command ID`) for every
subsequent probe-rs call, while OpenOCD kept talking to the same probe. A USB
port reset (`usbreset`), an `authorized` toggle and an unbind/bind did not clear
it; a physical replug will. Reads therefore go through OpenOCD with
`scripts/openocd-mg24-mini.cfg` — a Cortex-M33 target with **no flash driver**,
so it can read memory and cannot program the part.

| `pac_blink_base` | flashed, measured 6.30 toggle/s (~19 MHz FSRCO NOP loop) |
| `pac_blink_double` | flashed, measured 6.16 toggle/s, operator saw the pattern |
| `pac_timer_blink` | flashed, measured **1.02 Hz twice** (TIMER0 + HFRCOEM23) |
| `pac_i2c_scan` | flashed, ran to completion: **0 devices found** |
| `pac_gpio_button` | flashed and running: PC01 pull-up reads 1 (released) |

### The 1 Hz blink is calibrated, not assumed

`TOP` from datasheet arithmetic (20 MHz/1024/2 = 9765) measured 0.96/0.93 Hz;
scaled to 9229 it measures 1.02/1.02 Hz. This die's HFRCOEM23 is ~18.5 MHz.
A change of oscillator band invalidates the constant.

### I2C answered the wrong question, usefully

The scan completed and found **no device** at any address 0x08-0x77 on
PC04/PC05. Either the board is not seated on the Expansion Base, or the bus has
no pull-ups, or the OLED/RTC/BME680 of the base are not connected. This is a
diagnostic, not a failure of the master: the scan ran to completion with
bounded waits and reported `found=00000000`.

Expected addresses if the base is present: SSD1306 0x3C, PCF8563 0x51,
BME680 0x76 (0x77 if SDO is high).

## 8. Facts worth not rediscovering

`docs/04-reference/PAC-CLOCK-AND-TIMER-NOTES.md`:

- `CMU_CLKEN0` gates are mandatory; an ungated access is a precise bus error
  (`CFSR=0x00008200`) and the core parks in `HardFault_`.
- TIMER refuses `CFG` writes while enabled (`BFAR=0x40048004`) and `TOP` writes
  while disabled (`BFAR=0x4004801C`): order is `CFG → EN → TOP → START`.
- TIMER `IF.OF` cannot be cleared at all on this part — polling it spun at
  21 352 toggles/s; use the counter wrap.
- `EM01GRPACLK` has no LFRCO option, so TIMER0 cannot be given a 32.768 kHz
  time base; LETIMER0 (which can) counts once and stops.
- GPIO port registers are not at a fixed 0x10 stride: `PORTA_MODEL` 0x034,
  `PORTC_MODEL` 0x094, `PORTC_DOUT` 0x0A0, `PORTC_DIN` 0x0A4.
