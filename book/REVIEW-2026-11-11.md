# Book review — 2026-11-11

Review of `book/` against what the repository now is, and the update plan. Read the
"what is wrong" section as findings, not opinions: each line comes from comparing a
book claim with a file in the tree or a measurement on the board.

## State of the book

- `book/latex/main.tex` declares fifteen chapters across four parts.
- **Only chapter 1 has content** (`chapters/chapter-01-introduction/`, 1673 lines across
  six sections). Chapters 2–15 are placeholders: `\section*{This chapter content will be
  added}`.
- Chapters 1–2 directories exist; chapter 2 has only its shell file.
- No LaTeX toolchain in this container, so the book is compiled through a separate build host's
  `latex-compiler-shared` container.
- `book/TOC.yml` describes a more ambitious structure (fifteen chapters plus a
  progressive "LED blink evolution" running through four abstraction levels) that the
  LaTeX does not yet match.

## What is wrong today (chapter 1)

| book says | reality now |
|---|---|
| `efr32mg24-pac/` and `efr32mg24-hal/` at the top of the tree | everything lives under `crates/` after the restructure |
| `memory.x` with `RAM (rwx) : ORIGIN = 0x20000000, LENGTH = 256K` | `crates/efr32mg24-pac/memory.x` reserves the last 4 KB page as the SWD mailbox (`LENGTH = 252K`) and sets `_stack_start = 0x2003F000`; the 256 KB version linked a 4.5 KB stack |
| `runner = "probe-rs run --chip …"` as the flashing path | flashing goes through `scripts/flash.sh` — dry run by default, `--confirm` to write, refuses `load_min < 0x08006000`, verifies by read-back. `probe-rs` cannot even talk to this board's SAMD11 bridge reliably (documented desync) |
| `commander` / `JLinkExe` as alternatives | not installed here, and the Gecko bootloader region makes a careless write a brick; the guarded script is the only sanctioned path |
| `.cargo/config.toml` without `--nmagic` | `-C link-arg=--nmagic` is mandatory: without it LLD emits a `PT_LOAD` at `0x0800_0000`, inside the bootloader |
| probe-rs 0.18.0 in the transcript | 0.32.0 on the build host |

None of this is a typo: each one is a step a reader would follow and get a different
result from the one the book describes.

## What the book is missing that only this project can teach

These are the chapters worth writing, in the order the work actually happened, because
they are what makes the book different from every "hello, GPIO" tutorial:

1. **A bus that does not work: reading a defect honestly.** The on-chip I2C0 master
   cannot complete a read after a write on this die. The book should show the fourteen
   attempts, the evidence table, the workaround (bit-bang) and — importantly — the
   discipline of writing "open" instead of "fixed". Existing material:
   `docs/04-reference/I2C0-READ-DEFECT.md`.
2. **Finding a device that the pin map says is elsewhere.** The IMU is on PB2/PB3 with
   the two lines swapped relative to the Arduino variant, behind PD5.
   `pac_pullup_probe` (identify bus pins by external pull-ups) and `pac_imu_probe`
   (try pin pairs and both orders) generalise to any board without a schematic.
   `docs/04-reference/IMU-INVESTIGATION.md`.
3. **A peripheral whose writes are conditional.** `IADC.SINGLE` is writable only while
   the converter is enabled; writing it disabled is a precise bus fault that leaves the
   engine wedged across a core reset. `docs/04-reference/IADC-MIC-NOTES.md`.
4. **Verification without an instrument.** The mailbox at `0x2003_F000` read over SWD:
   how to prove a blink, a tone (`TOP = 19e6/(2·2700) = 3518`), a sensor (`|a| ≈ 1000 mg`)
   or a microphone (`rms≈550`) from numbers rather than from eyes and ears.
5. **Calibration against a wrong assumption.** `HFRCOEM23` starts at ~5 MHz and settles
   near 19 MHz; `asm::delay(n)` is not `n` cycles; `CNT` wraps every 3.4 ms. Three
   separate traps, each caught only by measuring. `04-reference/PAC-CLOCK-AND-TIMER-NOTES.md`.
6. **Layering under pressure:** the fall detector started in `hal::sensors::fall` and
   was moved out to a hardware-free crate. That correction — driver vs algorithm vs
   board — is the chapter on where code belongs.
7. **An accelerator that is not programmable by hand.** The reference manual removed the
   MVP register chapter in Rev 1.1; the supported path is compiling `.tflite` into
   register programs. `04-reference/MVP-NOTES.md`.

## Plan

Phase 1 (mechanical, safe now): fix the stale facts in chapter 1 — crate paths, the
`memory.x` figure and why, the flashing workflow (replace the `probe-rs run` runner with
`scripts/flash.sh`), probe-rs version, and add `--nmagic` where the linker is shown.

Phase 2 (the differentiator): one new chapter, `chapters/chapter-16-lessons/`, with the
seven topics above, each written as *problem → measurement → rule*, using the real logs.
Draft content prepared in `book/latex/chapters/chapter-16-lessons/` and wired into
`main.tex` as Part V.

Phase 3: fill chapters 4–8 (GPIO, clocks, timers, I2C, serial) from the PAC examples that
now exist, since each one has a measured result to quote instead of an invented one.

Phase 4: regenerate `book/TOC.yml` from `main.tex` so the two stop disagreeing, and
record in each chapter what the reader can *verify* at the end.

## Repaired in this pass

The book did not compile at all before this review: `pdflatex` stopped on the copyright
page and `xelatex` — the engine the book was written for — produced 44 errors. What was
wrong, and is now fixed:

| defect | consequence | fix |
|---|---|---|
| bare `\\` on empty lines in the copyright page | `There's no line here to end` — no PDF at all | one fact per line, each break with text before it |
| `\printindex` with no index package | undefined control sequence, fatal at the end | removed; the book has no `\index{}` entries |
| `{startup_s}` in a TikZ node | `Missing $ inserted`, cascading to a broken diagram | `startup\_s` |
| `[arrow]` style using `-Latex` without the library | undefined control sequence | `\usetikzlibrary{arrows.meta}` |
| Unicode em-dash, bullet, box-drawing characters | **silently disappear** in T1/lmodern — a sentence reading "not arbitrary it reflects" and trees with no lines | `newunicodechar` mappings for the text characters, and DejaVu Sans Mono for the code blocks under XeLaTeX |
| Figure 1.2 still showed the pre-restructure tree | the figure contradicted the text two lines below it | tree updated to `crates/`, with `memory.x` and `motion-detection/` |

Build, verified after every change:

```bash
tar cf - book/latex | ssh <build-host> 'cd ~/podman/latex-remote/efr32book && tar xf -'
ssh <build-host> 'podman exec --workdir /workspace/efr32book/latex latex-compiler-shared \
    xelatex -shell-escape -interaction=nonstopmode main.tex'
# rc=0, 0 errors, 0 "Missing character" warnings, 96 pages
```

`pdflatex` cannot build this book: the minted blocks contain box-drawing characters that
pdflatex rejects outright. `xelatex -shell-escape` is the engine, and the `newunicodechar`
plus `setmonofont` additions in the preamble are what make it render them instead of
dropping them.

## The rule this review keeps

A book about bringing up new hardware must not contain a step that was never run. Where
this repository has no verified answer — the MVP execution, the microSD card, the radio —
the chapter says so and stops, exactly as `docs/04-reference/I2C0-READ-DEFECT.md` does.

## Progress since this review

**Chapter 7 (I2C master mode) and chapter 14 (test-driven development) are written**, in `book/latex/chapters/chapter-07-i2c/` — five
sections, 104 pages total, 0 errors, 0 missing glyphs. It is built from what this project
measured rather than from what the reference manual says:

- the on-chip controller that could not complete a read, with the elimination table
  (six hypotheses, fourteen measurements) and the control experiment that decided it;
- the bit-banged master in four primitives, with the acknowledge explained as the only
  place the master reads;
- the two swapped bus lines, and the matrix search that found them, including the pin
  abstraction whose "which bus" parameter never reached a register;
- parity between two layers reading the same device, with gravity as the physical invariant.

The remaining chapters are still placeholders, and the seven proposed above are unchanged.

The testing chapter is chapter **14**, not 10: the plan numbered it 10 when Part III had fewer
chapters, and Part III grew four chapters afterwards. The label and directory were renamed to
match the physical order, because a file called `chapter-10-testing` printing as ``Chapter 14''
is exactly the kind of quiet mismatch that later becomes a wrong cross-reference.

Book now 110 pages: chapter 1, chapter 7 (I2C), chapter 14 (testing). Twelve placeholders
remain.
